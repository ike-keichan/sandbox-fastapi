# Command（コマンド）

よく使うコマンドは、[Makefile](../Makefile) にまとめています。`make <名前>` の形で実行します。

- [1. コンテナの操作](#1-コンテナの操作)
- [2. テストとコードの検査](#2-テストとコードの検査)
- [3. パッケージの操作](#3-パッケージの操作)
- [4. データベースの操作](#4-データベースの操作)
- [5. コンテナの中に入る](#5-コンテナの中に入る)

※ コマンドは、このリポジトリのフォルダの直下で実行してください。

※ 「起動中に使う」と書いたコマンドは、`make up` か `make upd` でコンテナを起動した状態で、別のターミナルから実行してください。

---

## 1. コンテナの操作

| コマンド | 内容 |
| --- | --- |
| `make setup` | 環境を作ります（ビルド、パッケージのインストール、テーブルの作成）。初回だけ使います。もう一度実行しても、データは消えません |
| `make up` | コンテナを起動します。記録がターミナルに出続けます。`Ctrl + C` で止まります |
| `make upd` | コンテナを、バックグラウンドで起動します |
| `make stop` | コンテナを止めます |
| `make restart` | コンテナを再起動します |
| `make build` | コンテナをビルドし直します。`Dockerfile` を変えたときに使います |
| `make ps` | コンテナの状態を表示します |
| `make down` | コンテナを削除します。データベースの中身は残ります |
| `make downv` | コンテナを、データベースの中身ごと削除します。**データは消えます** |

`make stop` と `make down` の違いは、コンテナを残すかどうかです。ふだんは `make stop` で足ります。

## 2. テストとコードの検査

どれも、起動中に使います。

| コマンド | 内容 |
| --- | --- |
| `make py/test` | テストを実行します |
| `make py/check` | コードを検査します。規則（`py/check-lint`）と書式（`py/check-format`）の両方を見ます |
| `make py/fix` | 検査の指摘のうち、自動で直せるものを直します。規則（`py/fix-lint`）と書式（`py/fix-format`）の両方を直します |

プルリクエストを作る前に、`make py/fix`、`make py/check`、`make py/test` の順に実行してください。

テストは、MySQL の代わりにメモリ上の SQLite を使うので、データベースの中身には影響しません。

## 3. パッケージの操作

| コマンド | 起動中に使う | 内容 |
| --- | --- | --- |
| `make py/add TARGET=<パッケージ名>` | はい | パッケージを追加します |
| `make py/add-d TARGET=<パッケージ名>` | はい | 開発用のパッケージ（テストや検査の道具）を追加します |
| `make py/update` | はい | パッケージを、`pyproject.toml` に書いた範囲の中で、最新にします |
| `make py/install` | いいえ | `poetry.lock` の記録のとおりに、パッケージをインストールします |

例：`requests` を追加する場合

```zsh
$ make py/add TARGET=requests
```

追加したパッケージは、すぐに使えます。コンテナのビルドは要りません。

`git pull` で `pyproject.toml` や `poetry.lock` が変わったときは、`make py/install` を実行してください。

## 4. データベースの操作

どれも、起動中に使います。

| コマンド | 内容 |
| --- | --- |
| `make db/migrate` | まだないテーブルを作ります。すでにあるテーブルとデータは、そのまま残ります |
| `make db/reset` | データベースにある全テーブルを削除して、作り直します。**データは消えます** |
| `make db/repl` | MySQL に接続して、SQL を入力できる状態にします。`exit` で抜けます |

モデル（テーブルの定義）を足したときは、`make db/migrate` を実行してください。

すでにあるテーブルの形（列の追加や変更）は、`make db/migrate` では変わりません。変えたときは、`make db/reset` で作り直してください（データは消えます）。

データベースを見るソフトウェア（TablePlus など）からつなぐ場合は、次の設定を使います。

| 項目 | 値 |
| --- | --- |
| ホスト | `127.0.0.1` |
| ポート | `33306` |
| ユーザー | `root` |
| パスワード | （なし） |
| データベース | `demo` |

## 5. コンテナの中に入る

どれも、起動中に使います。

| コマンド | 内容 |
| --- | --- |
| `make python/login` | API のコンテナのシェルに入ります。`exit` で抜けます |
| `make python/repl` | Python の対話環境を開きます。インストールしたパッケージや、`api` のプログラムを読み込めます。`exit()` で抜けます |
| `make db/login` | データベースのコンテナのシェルに入ります。`exit` で抜けます |
